# 数式・端末ガイド

## 数式が画像になる条件

ブロック数式（`$$ ... $$`）は、[RaTeX](https://github.com/erweixin/RaTeX) 0.1.15と同梱のKaTeXフォントでPNG画像を作り、Kitty Graphics Protocolで端末に送ります。追加のランタイムや外部のTeXは不要です。

画像で表示されるのは、次の**すべて**を満たす場合です。

1. `--plain`や`--graphics off`を指定していない（screenの中でもない）
2. 端末の画像対応の確認（Kitty Graphics Protocolの問い合わせ）に端末が応答する
3. セルのピクセル寸法と、文字色または背景色を端末から取得できる（ローカル画像は文字色・背景色がなくても表示します）

端末名だけで判断はしません。`--graphics auto`でも`--graphics kitty`でも端末の画像対応の確認への応答が必要です。macOSのTerminal.appはこの確認に応答しないため、ステータスの表示モードが`TEXT`になり、数式はTeXで表示されます（表やコードの色付けはそのまま使えます）。なお、文書にブロック数式も表示対象の画像もない場合は、照会そのものを省略します。

画像を作っている間や失敗したときは、その式だけTeXのソースで表示されます。文書全体が読めなくなることはありません。

### 対応している記法

分数、根号、総和、積分、ギリシャ文字、添字・上付き、行列、`aligned`で動作を確認しています。行列は環境によって括弧が変わります。

| 環境 | 括弧 |
|---|---|
| `matrix` | なし |
| `pmatrix` | 丸括弧 `( )` |
| `bmatrix` | 角括弧 `[ ]` |

KaTeX・LaTeXとの完全な互換性はありません。未知のコマンドや、外部ファイルの参照・実行、マクロ定義に関わるコマンドを含む式は、TeX表示になります。

### 画像化しないもの

- インライン数式（`$ ... $`）は、テキストで表示します。
- `--color never`のときは、数式全体が白か黒の1色になります（端末の文字色に近い方）。`\color`で付けた色も、この1色にそろえます。

数式画像の背景は透明です。端末の背景（半透明や背景画像を含む）がそのまま透けて見えます。端末の配色を表示中に切り替えた場合、数式の文字色は起動時（または`Ctrl+z`からの復帰時）の色のままです。

### 制限値

| 項目 | 上限 |
|---|---|
| 1つの式のソース | 16 KiB |
| 同時に画像化する式 | 2つ（子プロセス2つ） |
| 1つの式の生成時間 | 2秒 |
| 表示の高さ | 12行（セル） |
| キャッシュ | PNGとデコード後のデータの合計で128 MiB |
| tmuxの自動設定の待ち時間 | 150 ms |

画像化の同時実行数・生成時間・キャッシュは、ローカル画像と共通です。

## ローカル画像

対応端末では、Markdownの画像（`![代替テキスト](パス)`）のうち、次の条件を満たすものを画像で表示します。条件は数式と同じ（`--plain`・`--graphics off`でない、端末が画像対応の確認に応答する）で、文字色・背景色は必要ありません。

- **場所**：最上位の段落・見出しにある画像（強調の中を含む）。リスト・引用・表・リンクの中の画像は代替テキストで表示します。
- **参照先**：ローカルのファイル。相対パスはMarkdownファイルのあるディレクトリから探します（シンボリックリンクから開いた場合は、リンクのあるディレクトリ）。標準入力（`fumi -`）では起動したディレクトリから探します。`http:`・`https:`などのURL、`data:`、`?`や`#`を含む参照は読み込みません。
- **形式**：PNGとJPEG。拡張子ではなくファイルの中身で判定します。JPEGのEXIFの向きを反映し、透過PNGは透明部分を保ちます。アニメーションPNG（APNG）、GIF、WebP、SVGは代替テキストで表示します。

画像は本文から分けた行に表示し、代替テキストと参照先を画像の下に残します。読み込み中や表示できない場合は、その下に`[image: 生成中]`や`[image: ファイルが見つかりません]`のような理由を表示します。画像を表示できない端末や`--plain`では、v1と同じく文中に代替テキストを表示します。

- 本文の幅と12行に収まるように、縦横比を保って縮小します。元の大きさより拡大はしません。tmux内では最大297列です。
- `--color never`でも、画像は元の色で表示します。
- 画像ファイルの変更は監視しません。`R`や`--watch`で文書を読み直したときに、変更された画像も読み直します。
- Webから画像を取得することはありません。

| 項目 | 上限 |
|---|---|
| 1つの画像のファイル | 20 MiB |
| 画素数 | 2,500万画素 |
| 1つの画像の読み込み・変換 | 2秒 |
| 表示の高さ | 12行（セル） |
| 端末の画像対応の確認の応答待ち | 150 ms（自動設定とは別） |

## tmux

### 必要な条件

- 外側の端末がKittyの**Unicodeプレースホルダー**に対応していること
- tmuxがRGB色（トゥルーカラー）を保持できること
- 初めて起動するときと、`Ctrl+z`の中断から戻るときに、fumiのペインがアクティブであること

### パススルー設定の自動変更

数式を画像にする文書を開くと、fumiは`tmux`コマンドで**起動したペインだけ**に`allow-passthrough all`を設定します。`.tmux.conf`への追記は不要です。

- 変更するのは環境変数`TMUX_PANE`が指すペインだけです。他のペイン、グローバル設定、`.tmux.conf`は変更しません。
- `--plain` / `--graphics off`の場合や、ブロック数式のない文書では設定を変更しません。
- **自動で設定した値は、fumiの終了後もそのペインに残ります。**

### 仕組みと制約

- 画像はDCSパススルーで送り、本文と同じUnicodeプレースホルダーのセルとして配置します。
- tmux内では、数式画像の幅を最大297列に縮小します。
- リサイズ時は、セルの寸法と色をtmuxから取得し直します。
- `--color never`でも、画像IDを伝えるためにセルのRGB指定は使います。

自動設定の失敗、無応答、配置エラー、寸法の取得失敗、文字色・背景色の両方の取得失敗のいずれかが起きた場合は、TeX表示に切り替えます。

次の場合は対応していません。

- tmuxの入れ子
- 別の端末からの再接続
- 複数のクライアントへの同時描画
- Kitty画像には対応しているが、Unicodeプレースホルダーには対応していない端末

端末の画像対応の確認の後に端末側で起きたエラーや、未対応の配置命令を黙って無視する端末は、確実には検出できない場合があります。

## うまく表示されないとき

まず、次のどちらかで本文がテキストとして読めるか確認してください。

```sh
fumi --plain file.md
fumi --graphics off file.md
```

不具合を報告するときは、次の情報を添えてください。

- OS
- 端末とtmuxのバージョン
- フォント
- 画面サイズ
- 問題が再現する最小限のMarkdown

これまでに確認した端末は[v1検証記録](v1-verification.md)にあります。ここでは、PTY上の応答エミュレータによる転送の確認と、実際のGUI端末での目視確認を区別して記録しています。新しい環境で確かめる場合は[実端末チェックリスト](manual-testing.md)を使ってください。
