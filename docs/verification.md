# MVP検証記録

実施日: 2026-10-25（日本時間）。MVPの機能実装と、この環境で実行した検証の記録です。仕様11節の全端末・全OSへの対応を保証するものではありません。

## 環境

- macOS 27.0.1 / Build 26A434、Darwin 27.0.0、arm64。
- Rust 1.92.0、Python 3.9.6。CPUの型番・物理メモリ量はsandbox内では取得できなかった。
- PTYはPython標準ライブラリで作成。`TERM=xterm-256color`。シェル相当の監督プロセスを残してforeground process groupを設定し、ビューア終了後も同じ端末の属性を比較する。
- GUI端末・フォントは使用していない。Terminal.app / Ghostty / kitty / GNOME Terminal、tmux、SSH、Linuxは未検証。

## 実行したチェック

```sh
rtk cargo fmt --all -- --check
rtk cargo clippy --all-targets --all-features -- -D warnings
rtk cargo test --all-targets --all-features
rtk proxy python3 tests/pty_smoke.py target/debug/mdview
rtk cargo build --release --locked
rtk proxy python3 tests/pty_bench.py target/release/mdview
```

Rustの通常テストは16件。加えて通常実行ではignoreされるPTY専用の故障注入テスト1件を、PTYスクリプトから3種類の故障条件で実行する。PTYスクリプトは11グループを検証する。GUI端末の目視確認を代替するものではない。

端末属性の比較では、カーネルが一時的に立てる`PENDIN`（pending inputの再表示状態）だけを除く。macOSで、キー入力を読まずraw modeを解除する故障注入時にこの差が発生した。`ICANON`、`ECHO`、`ISIG`、速度、制御文字等の設定は比較する。スナップショットだけで端末復旧を判定していない。

`--color always`と空でない`NO_COLOR`を併用したPTY検証で、描画ライブラリ側の色抑止を見つけて修正した。auto/always/neverとNO_COLORの組合せは実際の出力でも確認する。

## 性能の参考測定

releaseビルド、`--plain`、1,048,576 bytes・10,000行のASCII文書。各行に行番号を入れ、空行を入れない長い一段落。120×40で起動し、1表示行下移動を100回、その後80×24へリサイズする。3回繰り返す。

プロセス起動／キー送信／リサイズ要求から、PTYのmaster側で最終描画シーケンスを受信するまでを測る。OS・PTY・Pythonの処理時間を含み、GUI端末の描画時間は含まない。仕様10.1節のflush時刻を内部計測した値とは区別する。

| 測定 | 結果（ms） | 初期目標との比較 |
|---|---|---|
| 起動・3回 | 337.5 / 96.2 / 95.6 | 初回は200 msを超過 |
| 移動・合計300回 | p95 19.0、中央値18.2 | 50 ms以内 |
| リサイズ・3回 | 106.4 / 110.6 / 93.7 | 200 ms以内 |

別のビルド直後の測定でも初回387.5 ms、続く起動69.6 / 72.1 msだった。初回と再実行で差があるが、OSのキャッシュを操作しておらず、原因は確定していない。初回起動時間を達成済みとは扱わない。初回だけの遅延の内訳計測・改善は残課題。

検索はv1のため未測定。32 MiB上限すべての描画時間・最大メモリ、日本語1 MiB、巨大表・数式多数の性能、クリーン環境での配布互換性も未測定。

## 実装と保留範囲

MVPのCLI・基本Markdown・日本語折り返し・移動・リサイズ・ステータス・スクロール可能なヘルプ・plain表示を実装した。入力ファイルの書換え、通信、リンク先起動、外部TeX実行、端末能力照会は行わない。

数式画像化、画像表示、検索、マウス、標準入力、監視、ハイライトは仕様の後続段階に残す。MVPは動作検証可能な状態だが、M09および実機端末による受け入れ確認を終えた公開リリースではない。
