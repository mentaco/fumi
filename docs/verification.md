## 初回CIの失敗と修正（2026-10-25）

[初回のGitHub Actions実行](https://github.com/mentaco/mdviewer/actions/runs/40165437830)は、Ubuntu・macOSともにfmtを通過し、Clippyで終了コード101となった。RustテストとPTY検証には進んでいない。macOSジョブ全体にはmatrixのfail-fastによるキャンセルも記録された。

共有されたCIログでは、ヘルプの位置表示に対して`clippy::manual_checked_ops`が警告されていた。従来のローカルRust 1.92.0では検出されなかったが、別の一時RUSTUP_HOMEとビルド出力先を使ったRust 1.99.1で同じ警告を再現した。

- 本文とヘルプの位置計算を`checked_div(...).unwrap_or(100)`へ変更した。画面に収まる場合は100%、スクロール可能な場合は先頭0%・末尾100%という表示規則を維持する。
- ヘルプが画面に収まる場合・スクロールする場合・リサイズ・本文へ戻る場合の進捗表示をテストへ追加した。Rust 1.92.0と1.99.1でfmt・Clippy・通常テスト17件が通過した。
- Rust 1.99.1でビルドした実行ファイルとテスト実行ファイルを使い、macOSのPTY検証11グループ（故障注入を含む）も通過した。
- checkout処理は初回CIでも成功しており、Node.js 20の非推奨警告は上記のClippy失敗と区別した。設定はNode.js 24を使用する`actions/checkout@v6`へ更新した（[公式説明](https://github.com/actions/checkout)）。
- `fail-fast: false`で両OSの結果を最後まで収集し、Rust・Cargo・Clippyのバージョンもログへ残す設定を追加した。

修正コミット`01ad8c1`の[GitHub Actions再実行](https://github.com/mentaco/mdviewer/actions/runs/40167729404)では、`ubuntu-latest`・`macos-latest`の両ジョブでfmt・Clippy・Rustテスト・PTY検証がすべて成功した。2026-10-25（日本時間）にGitHub APIで各ステップの成功を確認した。

これはGitHubホスト環境での自動・PTY検証の実績。ランナーのOSラベルは記録したが、OSイメージの詳細バージョンは未記録であり、LinuxのGUI端末・フォントの実機確認とは区別する。

## 実行したチェック

```sh
cargo fmt --all -- --check
cargo clippy --all-targets --all-features -- -D warnings
cargo test --all-targets --all-features
python3 tests/pty_smoke.py target/debug/mdview
cargo build --release --locked
python3 tests/pty_bench.py target/release/mdview
```

性能改善後のRustの通常テストは18件（高さだけのリサイズ、本文・ヘルプの上下端、最小サイズからの復帰の回帰テストを追加）。Rust 1.92.0 / 1.99.1でfmt・Clippy・通常テストが成功し、1.99.1でPTY検証11グループも成功した。加えて通常実行ではignoreされるPTY専用の故障注入テスト1件を、PTYスクリプトから3種類の故障条件で実行する。GUI端末の目視確認を代替するものではない。

端末属性の比較では、カーネルが一時的に立てる`PENDIN`（pending inputの再表示状態）だけを除く。macOSで、キー入力を読まずraw modeを解除する故障注入時にこの差が発生した。`ICANON`、`ECHO`、`ISIG`、速度、制御文字等の設定は比較する。スナップショットだけで端末復旧を判定していない。

`--color always`と空でない`NO_COLOR`を併用したPTY検証で、描画ライブラリ側の色抑止を見つけて修正した。auto/always/neverとNO_COLORの組合せは実際の出力でも確認する。

## MVP作成時の性能参考測定

releaseビルド、`--plain`、1,048,576 bytes・10,000行のASCII文書。各行に行番号を入れ、空行を入れない長い一段落。120×40で起動し、1表示行下移動を100回、その後80×24へリサイズする。3回繰り返す。

プロセス起動／キー送信／リサイズ要求から、PTYのmaster側で最終描画シーケンスを受信するまでを測る。OS・PTY・Pythonの処理時間を含み、GUI端末の描画時間は含まない。仕様10.1節のflush時刻を内部計測した値とは区別する。

| 測定 | 結果（ms） | 初期目標との比較 |
|---|---|---|
| 起動・3回 | 337.5 / 96.2 / 95.6 | 初回は200 msを超過 |
| 移動・合計300回 | p95 19.0、中央値18.2 | 50 ms以内 |
| リサイズ・3回 | 106.4 / 110.6 / 93.7 | 200 ms以内 |

別のビルド直後の測定でも初回387.5 ms、続く起動69.6 / 72.1 msだった。後続の[性能調査](performance.md)で、初回に大きく増える時間を`main`到達前まで切り分け、アプリ内のレイアウトを改善した。詳細な修正前後の結果・生データ・残課題は同記録を参照する。初回起動200 msの目標は引き続き未達。

検索はv1のため未測定。日本語1 MiB、巨大表・数式多数・長い一語は後続の性能調査で測定した。32 MiB上限すべての描画時間・最大メモリ、クリーン環境での配布互換性は未測定。

## 実装と保留範囲

MVPのCLI・基本Markdown・日本語折り返し・移動・リサイズ・ステータス・スクロール可能なヘルプ・plain表示を実装した。入力ファイルの書換え、通信、リンク先起動、外部TeX実行、端末能力照会は行わない。

数式画像化、画像表示、検索、マウス、標準入力、監視、ハイライトは仕様の後続段階に残す。MVPについてはユーザーの手動確認でも問題なしとの報告を受領した。M09の環境別実績と配布互換性の確認は残っており、全リリース条件を満たした扱いにはしない。
